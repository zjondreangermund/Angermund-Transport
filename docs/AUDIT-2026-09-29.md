# Transport audit — 29 September 2026

## Corrected findings

- Restored the missing inspections view, which threw during startup and left the loading screen over login.
- Require a configured webhook secret; validate GPS coordinates, truck and driver assignment. Phone locations cannot replace tracker positions or trigger movement automation, and older tracker messages cannot move the current position backwards.
- Recheck active accounts and roles for authenticated requests; revoke sessions and device credentials on password reset. Close affected event streams on account changes.
- Filter notification, scan and upload events by recipient/role. Restrict receipt and scan access. Keep notification read state per recipient.
- Exclude payroll data from operational roles and limit driver state to assigned work; preserve private payroll records when operational users save.
- Require a matching revision for state writes, serialize memory mutations and roll back failed operations. The browser merges disjoint changes, reports conflicts, retains pending edits across reloads and avoids overwriting edits during live refresh.
- Preserve server metadata instead of dropping it from browser saves. Empty central data no longer imports demonstration trips.
- Correct last-receipt diesel totals, invoice links, and receipt leg reassignment. Prevent deletion of legs with linked documents/receipts and changes to invoiced commercial values. Validate new-trip references and payroll months.

## Verification

`npm run check` and `npm test` cover startup/menu registration, authentication, notification visibility/read isolation, state concurrency, merge conflicts, payroll privacy, financial links, GPS authority and rollback behavior. Tests start an isolated memory-backed server without external providers.

A local Chromium session exercised all 25 admin navigation sections, simultaneous saves from two browser pages, offline edit recovery after reload, and the mobile command view. No JavaScript errors remained in those checks.

## Deployment and remaining runtime validation

Startup adds `users.auth_version` and `notification_reads` automatically. Refresh open browser sessions after rollout so they use revision-aware saves. No live data was modified and no deployment was performed by this audit.

Live PostgreSQL behavior, real tracker arrivals, OCR provider downloads, email/WhatsApp/push delivery and physical Android background behavior were not exercised here. Existing broad operational write permissions remain; this is not a certification that every possible user action or production integration is defect-free.
